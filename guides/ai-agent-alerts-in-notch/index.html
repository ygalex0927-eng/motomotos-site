Get notified when Claude Code or Codex finishes, fails or needs approval

Long agent runs finish while you’re in another window. motomotos lights up your MacBook’s notch the moment an agent is done, fails or waits for you — and one click takes you back to the right terminal.

Updated November 19, 2026

Agents it follows

Claude Code, Codex (the CLI and the desktop app), Grok CLI, DeepSeek Harness, Hermes and WorkBuddy. In Settings › Terminals & Approval, each agent has one switch that covers both its desktop app and its terminal command. Every open session gets a row with its own icon; click a row to jump back to its terminal.

Set up

  1. Install motomotos and open it. The welcome steps find the agents on your Mac and send a test alert.
  2. Claude Code: in Settings › Terminals & Approval › Claude Code hooks, click Install. It’s optional — without it you still see Claude Code working; with it, the notch also tells you when Claude Code waits for your approval. motomotos only adds its own entries to the hooks in ~/.claude/settings.json (backing the file up first) and leaves your other settings alone. Restart open Claude Code sessions afterwards. Uninstall removes only those entries.
  3. Grok CLI: install the Grok CLI hook on the same page.
  4. Codex and Hermes need nothing else — turn on their switches.

What you see

DoneA tick draws itself, sparks burst out, the cat is happy.
ErrorA red alert and a short shake of the head.
Waiting for youThe island grows into a card with the exact command, with amber light underneath.

Each kind of alert has its own sound, and you can turn off the pop-up banner in Settings › Appearance while keeping the cat and the sound.

Approve in the terminal or in the notch

  • Follow terminal (default): anything your terminal asks about is approved in the terminal. The island reminds you and jumps back to it.
  • Approve in the notch: sessions running with full access wait in the notch until you say OK.

Alerts from any other tool

Gemini CLI, Aider, a long build, a backup script: the motomotos command lights up the island the same way.

# send one
motomotos notify --title "Build done" --status done --app "Gemini CLI"

# wrap a command: done or error by exit code, with the time it took
motomotos run -- make test

# from Shortcuts, Raycast or a browser extension
open "motomotos://notify?title=Done&status=done&app=Raycast"

--status is done, error, waiting or info. The link only shows an alert; it never runs anything. If motomotos isn’t running, no alert is sent and nothing breaks; run always exits with your command’s own exit code.
